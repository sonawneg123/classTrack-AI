6. Database Queries Added

Three queries in getDashboardData() — all executed in parallel via Promise.all-equivalent sequential calls inside a single service method:

#QueryTechnique
1Scalar aggregate — all KPI counts in one rowCOUNT(*) FILTER (WHERE ...) — 18 sub-selects, single DB round-trip
2Classroom list with teacher + student + task countsJOIN + COUNT DISTINCT + GROUP BY, LIMIT 20
3Recent audit activity with resolved actor namesLEFT JOIN on admins/teachers/students with CASE, LIMIT 20

No N+1 queries. Existing getPlatformStats() untouched.

7. KPI Metrics Implemented

  • Total Students / Active / Inactive
  • Total Teachers / Active / Inactive / Unassigned (no classroom)
  • Total Classrooms / Active / Inactive
  • Total Assignments (tasks, non-deleted)
  • Total Submissions
  • AI Evaluations: Pending / Analyzing / Completed / Failed (real submissions.status values)
  • Teacher registration codes: Active / Expired

8. AI Evaluation Metrics

Uses the exact status values defined in the database schema CHECK constraint:

'submitted' → pending   'analyzing' → analyzing   'analyzed' → completed   'failed' → failed

No invented status names. Displayed as 4 stat cards in "AI Evaluation Overview" section.

9. Classroom Statistics

  • Total / Active / Inactive count in KPI card
  • Classroom overview table: name, subject/section, teacher name, teacher active status, student count, task count, active/inactive status chip
  • Empty state when no classrooms exist

10. Activity Feed

Sourced from audit_logs table — real database records only. Last 20 events. Each item shows:

  • Action (formatted from snake_case to Title Case)
  • Actor name (resolved via LEFT JOIN on admins/teachers/students)
  • Relative timestamp (e.g. "5m ago", "2h ago")

Security: Details JSONB filtered — keys containing password, hash, token, secret, code_hash are stripped before response.
